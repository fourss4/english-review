# ADR 0004: 백업 ZIP은 외부 라이브러리 없이 직접 구현

- 상태: 채택
- 일자: 2026-10-02
- 관련: ADR 0001(런타임 의존성 후보로 `fflate` 검토)

## 맥락
- 백업/복원(06단계)에 ZIP 쓰기·읽기가 필요하다.
- 녹음(AAC)은 이미 압축되어 있어 ZIP 압축 이득이 거의 없고, JSON은 작다.
- 외부 라이브러리를 쓰면 버전·라이선스·취약점 확인과 갱신 부담이 생기며, 작성 시점에 웹 검색으로 최신 상태를 확인할 수 없었다.

## 결정
- `app/js/zip.js`에 최소 ZIP 구현(약 130줄)을 둔다.
  - 쓰기: 무압축(STORE), UTF-8 파일명, CRC-32. 녹음 Blob은 복사하지 않고 조각으로 연결해 메모리를 아낀다.
  - 읽기: STORE와 DEFLATE 지원. DEFLATE는 브라우저 표준 `DecompressionStream('deflate-raw')` 사용 → PC에서 다시 압축한 ZIP도 복원 가능.
- 무결성은 manifest의 SHA-256(Web Crypto)으로 검증한다.
- 런타임 외부 의존성은 0개로 유지한다.

## 결과
- 장점: 의존성 0, 표준 ZIP이라 PC의 압축 프로그램으로도 열림(`unzip -t` 검증 통과).
- 한계: ZIP64 미지원 → 백업 전체 4GB 미만, 항목 65,535개 미만. 녹음이 많아 4GB에 가까워지면 "녹음 포함"을 끄고 텍스트·학습 기록만 백업하거나 기간별로 나누는 기능을 추가해야 한다.
- 암호화 ZIP은 지원하지 않는다(백업 파일 보관 위치로 보호).
