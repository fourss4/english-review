# 원본 샘플 분석 결과 (lesson1, 2026-10-02)

> 실제 샘플은 `private/raw-samples/`에만 있고 저장소에는 넣지 않습니다. 이 문서에는 **구조만** 기록하며, 예시는 가상 문장입니다.
> 녹음은 메타데이터(형식·길이)만 확인했고, 음성 내용은 열람·변환하지 않았습니다.

## 1. 녹음 파일
| 항목 | 값 |
|---|---|
| 파일명 | `<과정명> - <회차> <수업 제목>.m4a.mp4` (확장자가 두 번 붙음) |
| 컨테이너 | MP4 (m4a 계열), **영상 없음, 오디오만** |
| 코덱 | AAC, 48kHz, 모노, 약 61kbps |
| 길이·용량 | 약 21분 40초 / 약 10MB |
| 메타데이터 | 기술 정보만 있음(인코더·언어 등). 제목·이름 태그 없음 |

**설계 반영**
- `audio.mimeType`은 `audio/mp4`로 저장 (영상 대비 불필요)
- 파일명에서 **과정명·회차·수업 제목**을 자동 추출 → `course`, `lessonNo`, `title`
- 용량: 회당 약 10MB × 연 100~150회 ≈ **연 1~1.5GB**. Android Chrome에서 수용 가능한 수준으로 보이나 기기 여유 공간에 따라 다름 → 사용량 표시 + 오래된 녹음 정리 기능 유지
- 20분 원본은 그대로 두셔도 됩니다. STT 실험(06-1)에 20분 길이 파일이 필요하고, 파서 개발에는 녹음 내용이 필요 없습니다.

## 2. 채팅 텍스트 (복사본)
화자 표시·시간 표시가 **없음**. 내용은 강사가 수업 중 보낸 교정 노트 형식.

| 줄 유형 | 판별 규칙 | 의미 | 매핑 |
|---|---|---|---|
| 인사말 | 첫 줄, 이모티콘 포함 | 수업 시작 인사 | 무시(원문 보존만) |
| 핵심 표현 | 기호 없는 짧은 문장, 마지막 줄에 반복 | 수업 목표 표현 | `expressions[]` (`isKey: true`) |
| 패턴 | `xxx + A` 형태 | 문형 | 직전 핵심 표현의 `pattern` |
| `❌:` | 접두어 | 내가 말한 틀린 문장 | `corrections[].original` |
| `✅:` (❌ 바로 다음) | 접두어 | 최소 교정 | `corrections[].corrected` |
| `💡:` | 접두어(콜론 뒤 공백 없는 경우 있음) | 교정 이유 | `corrections[].explanation` |
| `✅:` (💡 다음) | 접두어 | 더 자연스러운 원어민 표현 | `corrections[].natural` (**신규 필드**) |
| `A. … B. …` | `A.`/`B.` 접두어 연속 2줄 | 핵심 표현 예시 대화 | 해당 표현의 `examples[]` |

- 따옴표가 곧은 따옴표(`"`)와 둥근 따옴표(`“ ”`)가 섞여 있음 → 정규화 필요
- 이모지 접두어(❌ ✅ 💡)가 핵심 구분자 → 이모지가 빠진 경우를 대비해 미리보기에서 수동 지정 가능하게

## 3. 코멘트 텍스트 (복사본)
문단 단위 자유 서술. 세 종류 문단이 섞여 있음.

| 문단 유형 | 판별 규칙 | 매핑 |
|---|---|---|
| 총평 | 첫 문단, 2인칭 서술(Your/You) | `feedback.summary` (**신규**) |
| 교정 해설 | 설명 문장 뒤에 `틀린 문장 + 교정 문장`이 구분자 없이 한 줄로 붙음 | 채팅의 같은 교정과 **원문 일치로 매칭**해 `explanationLong`에 추가 |
| 표현 카드 | `표현 - 품사 / 정의. 틀린 예문` + 다음 줄 개선 예문 | `expressions[]` (`partOfSpeech`, `definition`, `examples`) |

**OCR 흔적이 보입니다.** `y→v`, `g→q`, `o→c`, `l→i` 같은 글자 치환과 깨진 문자가 반복됩니다. 이미지에서 글자를 추출(텍스트 인식)해 복사하신 것 같습니다.
- **결정(2026-10-02): 교정 문장은 채팅 원문을 우선 사용** — 구현 완료(`app/js/parser/langdy-v1.js`)
- 대응 1: 앱에서 텍스트로 직접 복사할 수 있으면 그 방식을 권장
- 대응 2: 파서가 채팅 원문과 대조해 교정 문장의 OCR 오류는 채팅 쪽 문장을 우선 사용
- 대응 3: 미리보기 화면에서 의심 단어(사전에 없는 단어)를 표시해 수정 유도

## 4. 한국어 뜻 부재
채팅·코멘트 모두 영어로만 되어 있어 **한국어 뜻이 없습니다.** 한→영 카드와 "상황 → 표현" 연습에 한국어가 필요합니다.
- 방안 A: 가져오기 미리보기에서 직접 입력(선택)
- 방안 B: AI 표현 업그레이드 프롬프트에 "기존 표현의 한국어 뜻 채우기"를 함께 요청 → 결과 붙여넣기 시 자동 반영
- **결정(2026-10-02): 방안 B 채택** — ADR 0003 보완, `koFills[]`
- 기본값: 한국어가 없는 카드는 영→영(정의 보기) 또는 교정 카드로만 출제

## 5. 실제 샘플 변환 결과 (파서 langdy-v1)
| 항목 | 결과 |
|---|---|
| 파일명 → 과정·회차·제목·날짜 | 정상 추출 |
| 핵심 표현 / 패턴 / 예시 대화 | 1개 / 1개 / 4줄 |
| 교정(❌✅💡✅) | 6건 모두 4요소 추출 |
| 코멘트 표현 정의 | 1건(품사·정의·예문, 예문은 채팅 문장으로 대체) |
| 코멘트 해설 → 교정 연결 | 1건 |
| 분류 실패 문단 / 경고 | 0 / 0 |
| OCR 의심 단어 표시 | 7개 이상(예: `v`↔`y`, `q`↔`g` 혼동) |

## 5-1. 기호(❌✅💡)를 쓰지 않는 선생님 (2026-10-02)
- 규칙 변환으로는 교정이 0개가 됨 → 미리보기의 "AI로 교정 찾기"로 보완(ADR 0005). 가상 예: `samples/raw/lesson-demo-02/chat.txt`
- 같은 형식이 반복되면 실제 샘플(이름 가림)을 받아 변환 규칙에 추가할 예정
