## 1. 아키텍처 개요

```
[랭디 앱] --(수동 다운로드)--> [원본 파일: 녹음/코멘트/채팅]
                                     │
                     (선택) /tools CLI: STT·퀴즈 생성 → 표준 JSON/VTT
                                     │
                                     ▼
                       [가져오기 ZIP 또는 파일 선택]
                                     │
┌──────────────────────── 브라우저(PWA, 오프라인) ────────────────────────┐
│  Importer(원본 파서 → 표준 스키마 변환 + 검증)                          │
│        │                                                                │
│        ▼                                                                │
│  IndexedDB: lessons / audio(Blob) / cards / reviewLog / bookmarks /     │
│             generated / meta                                            │
│        │                                                                │
│  화면: 수업 목록 · 카드 복습(SM-2) · 오디오 구간반복 · 채팅 검색 · 설정    │
│        │                                                                │
│  Exporter: 전체 백업 ZIP(manifest + 표준 포맷) / Anki TSV               │
└─────────────────────────────────────────────────────────────────────────┘
       ▲
       │ 앱 코드만 정적 호스팅(GitHub Pages / Cloudflare Pages 등). 데이터는 업로드하지 않음
```

### 핵심 결정
| 항목 | 결정(안) | 근거 |
|---|---|---|
| 앱 형태 | 정적 PWA (HTML + ES Modules) | 서버 불필요, 모바일 홈화면 설치 가능 |
| 빌드 | 빌드 단계 없이 시작(ES Modules + JSDoc 타입) | 도구 교체 시 빌드 설정 이관 부담 제거. 규모 커지면 Vite 도입을 ADR로 결정 |
| 저장소 | IndexedDB (얇은 래퍼 직접 작성) | 표준 API, 의존성 없음 |
| ZIP 처리 | `fflate` (MIT) 1개만 런타임 의존성 후보 | 경량. 도입 시 버전·라이선스·취약점 확인 후 ADR 기록 |
| 스키마 검증 | 런타임: 수작성 경량 검증 / 테스트: `ajv`(dev 전용) | 런타임 의존성 최소화 |
| 간격반복 | SM-2 | 공개 알고리즘, 구현 단순, Anki와 개념 호환 |
| 오프라인 | Service Worker로 앱 셸 캐시 + `navigator.storage.persist()` 요청 | 저장소 자동 정리 위험 완화 |

> 주의: Service Worker는 `https://` 또는 `localhost`에서만 동작합니다. 파일을 더블클릭해서 여는 `file://` 방식으로는 오프라인 기능이 동작하지 않으므로 정적 호스팅이 사실상 필요합니다.

## 5. STT(녹음 → 텍스트) 대안 비교

STT는 MVP 필수 기능이 아닙니다. 채팅·코멘트만으로 복습은 가능하며, 녹음 스크립트가 필요할 때 `/tools`에서 별도로 실행해 `transcript.vtt`를 만드는 구조를 권장합니다.

| 방식 | 예시 | 장점 | 단점 | 개인정보 |
|---|---|---|---|---|
| PC 로컬 실행 | whisper.cpp, faster-whisper (오픈소스) | 무료, 데이터가 PC 밖으로 나가지 않음, 오프라인 | 설치 필요, CPU만 있으면 느릴 수 있음 | 가장 안전 |
| 브라우저 내 실행 | Transformers.js 기반 Whisper | 설치 불필요 | 모델 다운로드가 크고 모바일에서 느리거나 불안정 | 안전 |
| 외부 API | 클라우드 STT/LLM 공급자 API | 빠름, 정확도 높음, 화자 분리 지원 경우 있음 | 유료, API 키 관리 필요, 공급자 종속 | 강사 음성이 외부로 전송됨, 약관·동의 확인 필요 |

권장: 로컬 Whisper 계열을 `/tools/stt`로 감싸서 WebVTT를 출력합니다. 외부 API는 인터페이스만 열어 두고, 사용 시 전송 동의를 명시적으로 받습니다.
(도구별 라이선스·현재 버전·성능 수치는 도입 시점에 확인 필요)

## 6. 확인 질문 (한 번에 답변 부탁드립니다)

1. **원본 형식**: 랭디에서 받을 수 있는 형태가 각각 무엇인가요?
   - 녹음: 파일 다운로드 가능 여부, 확장자(mp3/m4a 등)
   - 코멘트: 텍스트 복사 / PDF / 이메일 / 앱 화면만 가능
   - 채팅: 내보내기 가능 여부, 아니면 복사·붙여넣기
2. **사용 기기**: 주로 iPhone인가요, Android인가요? PC에서도 쓰시나요?
3. **호스팅**: 개인 GitHub 계정 등으로 GitHub Pages / Cloudflare Pages를 쓸 수 있나요? (오프라인 기능에 https 필요)
4. **STT**: 녹음 스크립트가 필요한가요? 필요하면 STT를 돌릴 PC가 있나요?
5. **분량**: 주당 수업 횟수와 회당 녹음 길이(저장 용량 산정용)
6. **카드 방향**: 영→한, 한→영, 교정 문장 고르기(틀린 문장 → 맞는 문장) 중 원하시는 것(복수 선택 가능)
7. **LLM CLI**: 추가 퀴즈 생성 기능을 쓸 계획이 있나요? 있다면 쓰려는 공급자가 있나요? (없으면 mock만 구현)

샘플 준비 방법은 [`sample-request.md`](./sample-request.md)를 참고해 주세요.

## 7. 확정 사항 (2026-10-02 답변 반영)

| 항목 | 답변 | 설계 반영 |
|---|---|---|
| 원본 형식 | 녹음 mp4 다운로드, 코멘트·채팅 텍스트 복사 | 가져오기 화면 = **mp4 파일 선택 + 코멘트/채팅 붙여넣기 칸 2개**. ZIP 가져오기는 백업 복원용으로만 사용. 붙여넣은 원문은 `source.raw`에 보존해 파서 개선 시 재변환 |
| 기기 | Android 전용 | Android Chrome 기준 개발·테스트, 홈화면 설치(PWA) 전제. 폴더 선택 기능 불필요 |
| 호스팅 | GitHub Pages(가입 예정) | [`github-pages-guide.md`](./github-pages-guide.md). 무료 플랜은 공개 저장소 전제이므로 코드만 올리고 데이터는 절대 올리지 않음 |
| STT | 필요 | 단계 분리(아래 7-2). MVP는 STT 없이 출시, 이후 추가 |
| 분량 | 주 2~3회 × 20분 | 연 약 100~150회. mp4가 오디오만이면 1회 수 MB~20MB 수준(비트레이트에 따라 다름), 영상 포함이면 훨씬 큼 → **샘플로 확인 필요**. 저장 공간 표시 + 오래된 녹음만 삭제(텍스트·카드 유지) 기능 포함 |
| 복습 방식 | 다 좋음 | 아래 7-1 |
| AI 퀴즈 | 추천 요청 | 아래 7-3, ADR 0002 |

### 7-1. 복습 기능 구성 (오프라인, AI 불필요)
| 기능 | 원천 데이터 | 방식 |
|---|---|---|
| 뜻 카드 영→한 / 한→영 | 새 표현 | 카드 뒤집기 + SM-2 자기평가 |
| 문장 고치기 | 오류 교정 | 틀린 문장 제시 → 직접 입력 → 정답과 차이 강조 표시 |
| 빈칸 채우기 | 표현의 예문 | 예문에서 해당 표현을 빈칸 처리 |
| 객관식 | 새 표현 | 오답 보기를 다른 수업 표현에서 자동 추출 |
| 구간 듣기·쉐도잉 | 녹음 + 북마크 | A-B 반복, 속도 조절, 내 목소리 녹음 후 번갈아 듣기 |
| 받아쓰기 | STT 스크립트(2단계) | 구간 재생 → 입력 → 비교 |
| 오늘의 복습 | 전체 | 오늘 할 카드 수와 연속 학습일 표시 |

### 7-2. STT 단계 계획
1. **MVP:** STT 없이 녹음 + 코멘트 + 채팅으로 복습
2. **실험:** 브라우저 내 Whisper(Transformers.js)를 Android에서 20분 샘플로 테스트 — 속도·발열·정확도 측정 후 채택 여부 결정
3. **대안:** 개인 PC에서 로컬 Whisper(faster-whisper 또는 whisper.cpp) 스크립트(`/tools/stt`) 실행 → `transcript.vtt` 생성 → 앱에서 가져오기
4. **비권장:** 외부 STT API — 강사 음성이 외부로 전송되므로 사용 시 랭디 약관·당사자 동의 확인 필요

> 회사 PC에 오픈소스 도구를 설치하는 것은 사내 IT 규정 확인이 필요합니다. 개인 PC 사용을 권장합니다.

### 7-3. AI 표현 업그레이드 + 연습 3종 (ADR 0003, 기존 AI 퀴즈 대체)
- AI가 녹음 스크립트에서 OPIc IH 수준의 slang / idiom / 더 좋은 표현 **3개**를 설명·예시와 함께 제시
- 연습: ① 바꿔 말하기 드릴(내 원래 발화 재생 → 업그레이드 표현으로 말하기·녹음 비교) ② 상황 → 표현 떠올리기 카드(간격반복) ③ OPIc 미니 답변 챌린지(질문에 표현을 넣어 60~90초 답변 녹음 + 체크리스트)
- STT가 전제 조건이 되므로 STT를 M5 직후로 앞당김
- 프롬프트 템플릿: `/app/prompts/expression-upgrade.md`

### 7-4. AI 연동 방식 — "프롬프트 복사 → 결과 붙여넣기" (ADR 0002, 유지)
앱이 API를 직접 호출하지 않고, AI에게 줄 프롬프트를 만들어 복사해 주면 사용자가 원하는 AI 채팅(Claude, ChatGPT, Gemini 등)에 붙여넣고, 받은 JSON을 다시 앱에 붙여넣는 방식입니다. 상세는 [ADR 0002](./decisions/0002-ai-quiz-prompt-relay.md).

| 방식 | API 키 | 서버 | 공급자 교체 | Android 단독 | 평가 |
|---|---|---|---|---|---|
| **프롬프트 복사·붙여넣기** | 불필요 | 불필요 | 즉시 가능 | 가능 | **추천** |
| PC용 CLI(API 호출) | 필요 | 불필요 | 코드 수정 | 불가(PC 필요) | 대량 생성 시 보조 |
| 앱에서 API 직접 호출 | 브라우저에 저장 | 불필요 | 코드 수정 | 가능 | 키 노출·데이터 전송 위험으로 비권장 |

## 8. 재설계 (v0.8.0, 2026-10-02 사용자 피드백 반영 — ADR 0006·0007)
- 7-2·7-3·7-4는 대체됨: STT와 AI 추출은 PC 수업 처리기(`tools/`)에서 Claude API(교체 가능)로 자동 수행, 앱은 패키지만 읽음.
- 완료: 처리기(STT·가림·추출·문제 생성·검증·패키지·주간 요약, 테스트 14), 앱 v0.8.0(패키지 가져오기, 업그레이드 3개, 자동 채점 문제 4종, srs2, 오답 복습, 다음 수업 준비, OPIc 모의 답변, 주간 요약, 학습 기록 내보내기, v1 데이터 자동 변환, 테스트 51), 브라우저 스모크 테스트(가짜 AI 결과).
- 남은 확인: 실제 PC에서 faster-whisper 음성 인식 품질·속도, 실제 Claude 응답 품질(프롬프트 `tools/prompts/*.md` 조정), 휴대폰 실기기 동작.
